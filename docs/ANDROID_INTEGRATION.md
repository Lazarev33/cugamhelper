# Интеграция Cugam Helper Android

Мобильный проект стартует отдельным этапом после серверной приёмки. Рабочие алгоритмы и ввод Bluetooth HID находятся в приложении. Сервер получает рабочий набор только после явного нажатия «Отправить в Telegram».

1. Определите URL сервера из параметров установки. Перед привязкой запросите версию API.
2. Выполните привязку из [API.md](API.md). Числовой Telegram ID только ограничивает, кто может подтвердить запрос. Он не является авторизацией.
3. Храните токены в защищённом хранилище Android с опорой на Keystore. Исключите их из резервных копий и диагностического вывода. Применяйте штатную проверку TLS.
4. Синхронизируйте `/sync`, `/catalog` и `/features` условными запросами. Заменяйте локальный каталог только после получения новой согласованной версии. При 401 попытайтесь однократно обновить сессию. При подтверждённом отзыве очистите токены и прекратите серверное взаимодействие.
5. Ограничения общего уровня и Android применяются совместно. Локальные настройки клиента могут сузить эти разрешения. Значение `android_client_released:false` относится к готовности Android-реализации.
6. Отправляйте НСУ через стабильный ID. Опрос статуса раз в 2–5 секунд. Учитывайте `confirmed_parts`, остаток срока и неопределённый результат. Пустой факт в двух проходах в текущем контракте отклоняется. Сохраните исходную сессию локально до получения подтверждения от пользователя, если это требуется для повторной отправки.

`offline_lease_seconds: 0` означает отсутствие серверной офлайн-лицензии. Офлайн нельзя проверить действительность доступа или получить новые данные с сервера. Решение о допуске к локальным алгоритмам и правилам использования локальной копии каталога принимает владелец на Android-этапе. API не синхронизирует рабочие списки и не может отозвать уже сохранённые на телефоне значения.

Для ручной проверки используйте `python docs/test_client.py https://<домен> <тестовый Telegram ID>` на разрешённом тестовом боте. Скрипт отправляет только демонстрационные строки. Автоматические проверки в `test_infrastructure.py` подставляют контролируемый транспорт и рабочий токен не используют.
