# Cugam Helper REST API v1

Базовый адрес `https://<домен>/api/v1`. В локальном режиме используйте `http://localhost:8765/api/v1` через SSH-туннель. Контракт [OpenAPI 3.1](openapi.json) генерируется приложением и доступен как `GET /api/v1/openapi.json`. Тело запроса JSON, ошибки содержат машинный ключ `{"code":"access_revoked"}`. Клиент самостоятельно переводит его для своего интерфейса. Тела запросов с секретами и ответами следует исключить из журналов Android.

| Метод и путь | Применение |
| --- | --- |
| GET /health, /version | Публичная проверка HTTP и версия контракта |
| POST /auth/link/start | Начать привязку Android. Ответ 201 содержит challenge, telegram_url, expires_at |
| POST /auth/link/exchange | Обменять подтверждённый challenge и verifier на токены |
| POST /auth/refresh | Ротация пары, тело `{"refresh_token":"…"}` |
| POST /auth/logout | Отключить текущее устройство, ответ 204 |
| GET /auth/me | Текущий Telegram ID, device_id и разрешение экспорта |
| GET /devices?page=0 | Устройства собственного аккаунта, постранично |
| DELETE /devices/{id} | Отключить своё устройство, ответ 204 |
| GET /catalog, /catalog/version | Активный каталог с ревизией и ревизия отдельно |
| GET /features, /sync | Правила сервера, итоговые разрешения Android, ревизии и состояние онлайн-допуска |
| POST /telegram/exports | Поставить НСУ в оперативную очередь, ответ 202 |
| GET /telegram/exports/{request_id} | Проверить статус своего запроса с того же устройства |
| DELETE /telegram/exports/{request_id} | Отменить ещё ожидающий запрос |
| GET /admin/status | Системные счётчики для веб-сессии администратора, а не для Bearer Android |

Для защищённых мобильных операций устанавливайте `Authorization: Bearer <access_token>`. Токен действует 10 минут. Семейство refresh действует до 30 суток от привязки. Ротация атомарно заменяет оба токена. Параллельные refresh-запросы следует объединять в один, сохраняя новую пару атомарно. После потери ответа о ротации может понадобиться повторная привязка. Данные каталогов и переключателей возвращаются с ETag. Передайте предыдущий ETag как If-None-Match. Ответ 304 не содержит тела. Отсутствие доступа проверяется до 304.

## Привязка

Создайте 32 случайных байта, закодируйте Base64URL без дополнения. Это `verifier` длиной 43 символа. Отправьте SHA-256 от его ASCII-представления в шестнадцатеричном виде. Кодировка текста UTF-8.

```json
{"telegram_id":10003,"device_name":"Тестовый терминал","app_version":"0.0.1","proof_sha256":"<64 hex>"}
```

Откройте URL из ответа. После подтверждения пользователем отправьте `{"challenge":"<challenge>","verifier":"<исходный секрет>"}` в `/auth/link/exchange`. При 409 с `link_pending` допустимо опрашивать с паузой 3–5 секунд до истечения пяти минут. Для новой попытки создайте новый verifier. Запрет или истечение завершают попытку. `chat_id` в мобильных моделях отсутствует.

## НСУ

Пример для режима пар:

```json
{
  "request_id":"sample-request-00001",
  "mode":"pairs",
  "report":{"matched":1,"expected":2,"missing_count":1,"extra_count":0,"missing":[" 00B"]},
  "first":["A-001"," 00B","A-001"]
}
```

Для двух проходов используйте `mode: "two_passes"`, передайте эталон в `first`, факт в `second`. При наличии недостающих или лишних экземпляров отчёт сообщает о расхождении. Сервер проверяет структуру и границы, форматирует отчёт и пересылает переданные строки. Расчёт выполняет приложение. Счётчики в примере являются результатами клиента. Значения не исправляются и не дополняются на сервере.

В одном запросе до 512 КиБ, до 2000 строк в каждом массиве и до 4000 в сумме. Длина строки до 512 печатных символов, один идентификатор без перевода строки. До 36 частей на экспорт, форматирование отключено. Telegram принимает отдельный отчёт, отдельно `first`, затем `second`. Длинные части разбиваются по границам строк до 4000 единиц UTF-16. Общая очередь вмещает восемь активных заданий, одно на пользователя, новый экспорт не чаще одного раза в восемь секунд на пользователя. Запрос на привязку ограничен до 12 запросов в минуту на IP, обмен и обновление до 60, прочие до 180. Публичные пределы могут быть строже при общей загрузке.

| Статус | Значение |
| --- | --- |
| queued | Сервер принял задание |
| sending | Сервер передаёт части |
| delivered | Telegram подтвердил все части |
| partially_delivered | Подтверждена часть сообщений, оставшиеся не отправлены или отклонены |
| failed | Отправка отклонена или транспорт недоступен |
| delivery_unknown | Результат одной попытки неизвестен, `confirmed_parts` считает лишь подтверждённые части |
| cancelled | Отменено до подтверждения части |
| expired | Истёк дедлайн, подтверждённых частей нет |

Экспорт действует до двух минут, история статуса держится до десяти минут с приёма. Повторите тот же ID с тем же содержимым, чтобы проверить или безопасно восстановить исходный запрос в пределах его жизненного цикла. Изменение содержимого при прежнем ID даёт 409. При неизвестном результате клиенту следует предложить проверить чат. Перезапуск API теряет очередь, статусы и оперативную идемпотентность. После потери состояния повтор может создать дубликат.
