# Восстановление

| Событие | Действие |
| --- | --- |
| Ошибка подписи, ZIP или отсутствие GitHub | Оставить активный выпуск, перепроверить источник и ключ |
| Неудачный запуск после переключения | Проверить возвращённую ссылку, unit-файлы и состояние служб |
| Отказ worker, памяти или IPC | Проверить worker-status и systemd, повторить прерванную операцию |
| Остановка бота или API, перезагрузка | Проверить состояние служб, незавершённая RAM-очередь теряется |
| Telegram недоступен | Учитывать подтверждённые части и неизвестный исход, проверить чат перед повтором |
| Недостаток места или непригодная конфигурация | Освободить место вне рабочих каталогов и восстановить проверенную конфигурацию |
| Компрометация ключа | Остановить обновление, отозвать PEM в доверенном каталоге, перепроверить установленный выпуск |
| Отзыв администратора | Проверить отзыв веб-сессии. Владелец может восстановить свой вход из консоли |

Для ручного возврата выпуска остановите API и бота, сохраните состояние и проверьте происхождение локального предыдущего архива. Восстановите его исходные unit-файлы и ссылку релиза, перезагрузите конфигурацию systemd, проверьте запуск. Держите порог обновлений. Если локального доверенного выпуска нет, нужен новый подписанный выпуск.

sudo numberbot backups показывает целостность и хеш. sudo numberbot restore ИМЯ_КОПИИ готовит закрытую рабочую копию и требует ввода RESTORE. Останавливаются API и бот, после чего БД атомарно заменяется. При ошибке старта возвращается исходный экземпляр. При открытом WAL или журнале замена прекращается. Возврат из копии сбрасывает роли, допуски, устройства, шаги подтверждения и сессии. Владелец из системных настроек заново выдаёт допуски. Каталог, журнал и настройки сохраняются.
