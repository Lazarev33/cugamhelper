# Доверенный выпуск

Ed25519 через OpenSSL 3 подписывает точные байты JSON. Манифест связывает ZIP, SHA-256, размер, версию, Git SHA, срок и платформу. Minisign добавил бы отдельное средство bootstrap. TUF дал бы делегирование и отдельную проверку свежести, усложнив эксплуатацию. Keyless-подпись в том же CI сохраняет зависимость от доверия к этому CI. Используется один офлайн-ключ издателя.

## Начало доверия

Получите secure_release.py, его SHA-256 и публичный Ed25519-ключ с отпечатком через подтверждённый владельцем канал. Проверьте их до привилегированного запуска. Требуются Linux x86-64, systemd, системный CPython 3.10 или 3.12, openssl, curl, python3-venv и сертификаты CA.

```sh
sudo install -d -m 0755 /etc/tg-number-cleaner
sudo install -d -m 0700 /etc/tg-number-cleaner/release-trust/keys
python3 -I secure_release.py key-id owner-public.pem
```

Сравните вывод с отпечатком владельца и установите PEM как файл с именем <отпечаток>.pem в release-trust/keys. Подготовьте резервную копию. Прежний updater читает ветку и для перехода не применяется. Локальная проверка использует каталог local-trust/keys с подтверждённым PEM.

```sh
python3 -I secure_release.py --trust ./local-trust verify Cugam-Helper.zip Cugam-Helper.manifest.json Cugam-Helper.manifest.sig
sudo /usr/bin/python3 -I /root/trusted/secure_release.py install Cugam-Helper.zip Cugam-Helper.manifest.json Cugam-Helper.manifest.sig
```

Привилегированная установка повторно проверяет файлы в закрытом каталоге доверия. ZIP извлекается с проверкой имён, размера и типа. Сборочная служба работает от отдельного UID, пишет только своё окружение и tmpfs. Root переносит системные файлы напрямую из проверенного ZIP. Установка Python применяет --require-hashes и --only-binary=:all:. Подпись и lock не доказывают безопасность компонентов.

## Обновление и ротация

После выпуска три стандартных артефакта публикуются как обычный GitHub Release. sudo numberbot update отклоняет неизвестный ключ, повреждённый пакет, изменение ZIP при той же версии и снижение версии. Новый порог записывается до переключения. Автоматический откат возвращает прежние файлы и службы, сохраняя порог. Для ручного аварийного возврата используйте проверенный локальный выпуск и его unit-файлы по [процедуре восстановления](DISASTER_RECOVERY.md).

Офлайн-ключ создаёт и хранит владелец. Для ротации сначала доставьте новый PEM и сверьте отпечаток у операторов. Затем переключите подпись и удалите отозванный PEM. При компрометации остановите обновления, зафиксируйте состояние, отзовите ключ локально и перепроверьте установленный выпуск. Новый манифест должен пройти порог принятой версии. Удаление PEM не останавливает запущенные процессы.

tooling/package_release.py собирает ZIP по Git SHA. tooling/lock_dependencies.py формирует lock на основе проверенного отчёта pip и метаданных PyPI. CI использует только одноразовый лабораторный ключ. Приватные ключи не входят в ZIP.
