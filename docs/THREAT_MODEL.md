# Модель угроз

| Граница | Активы и полномочия | Снижение риска |
| --- | --- | --- |
| Telegram и API v1 | Токены, сессии, лимиты, рабочие результаты | Подтверждение личного чата, verifier, повторная проверка допуска перед доставкой, лимиты и RAM-очередь |
| Web Control Center | Роли, глобальные функции, каталог, устройства | Текущая роль, Secure/HttpOnly cookies в HTTPS, Origin, CSRF, одноразовый VPS-допуск для критических записей |
| Worker | XLSX, DOCX и фото, декодеры | Отдельный UID, сокет бота, кадры ограниченного размера, тайм-ауты, закрытые каталоги и запрет создания сетевых сокетов |
| GitHub / PyPI | Код, зависимости, unit-файлы, root-updater | Закреплённый Ed25519, подписанные SHA-256, версия и срок, непривилегированная подготовка, фиксированные колёса |
| SQLite и копии | Допуски, история, привязанные устройства | Права ОС, согласованный backup, утверждённые сроки, очистка авторизаций при ручном restore |

Компрометация бота остаётся серьёзной: у него есть доступ к нужным служебным данным. Worker снижает последствия дефекта декодера, сохраняя зависимость от ядра. Владелец GitHub и CI могут скрыть новый релиз. Порог версии и срок ограничивают откат и заморозку, но не доказывают свежесть. Доверенный ключ и исходный bootstrap — корни доверия. Утечка SQLite или копии остаётся риском, файлы не шифруются приложением. Root, гипервизор, окружение и Telegram вне этих гарантий. Соответствие ASVS, NIST или SLSA не сертифицировалось.
