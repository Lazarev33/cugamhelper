# Архитектура Cugam Helper

`tg-number-cleaner.service` ведёт единственный polling aiogram. Существующие модули обрабатывают Telegram-команды из того же SQLite. `cugam-api.service` запускает один Uvicorn-процесс на loopback и обслуживает REST и Control Center. Тонкий серверный интерфейс использует HTML, CSS и небольшой JavaScript без JS-сборки или внешних ресурсов. API доступен при остановленном боте. Для доставки API держит очередь в памяти и вызывает Unix-сокет бота. Бот проверяет сессию и отправляет сообщения через существующий Outgoing, включая лимиты и обработку 429.

Обе службы используют каталог, сотрудников и роли SQLite. Конкурентное редактирование каталога и сотрудников контролируется версиями записей. Атомарные операции SQLite включают изменения полномочий и журнал. Триггеры отзыва закрывают токены вне зависимости от интерфейса, из которого отозван доступ. При восстановлении доступа старые токены не оживают. Общие переключатели читаются из прежнего features.json до первой записи общего снимка в SQLite. После записи TUI, бот и веб-панель обращаются к SQLite. Клиентские переключатели накладывают дополнительные ограничения. Доступ к администрированию каталога не зависит от доступности пользовательской выдачи.

Расширение SQLite добавляет новые таблицы и триггеры, оставляя `user_version=2`. Первое применение сохраняет согласованный снимок `catalog.sqlite3.pre-infrastructure.bak`. При отказе переключение релиза откатывает файлы и службы без восстановления старой копии базы. Скопированный snapshot предназначен для аварийного восстановления и может содержать устаревшие права. При ручном возврате к 2.7.6 остановите и отключите `cugam-api.service`. Старый бот игнорирует новые таблицы и читает прежний features.json. Перед ручным возвратом проверьте его настройки. Новые роли, каталог и журнал остаются в основной SQLite.

Веб-панель разделяет роль владельца и администратора. Назначение администраторов, общие и клиентские переключатели доступны владельцу; запуск служб, токен, порт, DNS и TLS находятся на стороне VPS. Веб-диагностика использует фиксированные чтения состояния и узкий вызов Telegram getMe. Systemd запускает API без root и без доступа к файлу bot.env в его mount namespace.

В v3.1.0 systemd запускает отдельного worker для документов и фото. Один клиент передаёт один запрос по сокету. Протокол ограничен размерами и сроком. Изменение ключей, системных настроек и восстановление БД выполняются на VPS. См. [модель угроз](THREAT_MODEL.md) и [цепочку поставки](SUPPLY_CHAIN.md).
